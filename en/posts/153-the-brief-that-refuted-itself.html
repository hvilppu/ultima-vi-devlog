The Brief That Refuted Itself

A brief's headline table said which text two code sites share. A correction two sections below it, measured and right, already determined that the table was wrong. Nobody went back to the table, so the document shipped holding the fact that refuted its own finding.

What the slice was

Four places in the original speak a spell's words of power. Casting brackets them after the name; enchanting a staff prints them alone; looking at a spellbook page adds an opening line, the name and the reagents; using a charged item has its own opening and then runs the spell.

One was built. These three were not. A shared "speak the words" routine would get three of the four wrong in a way no test of the fourth could see, which is the whole reason the slice existed.

And the table

My brief listed each site's formats by their offsets and concluded: only one pair is shared, between the two sites in the same file.

That was wrong twice. As text, the syllable pair is shared by all four sites. As rows, the two sites in the first file share both syllable rows outright, so enchanting shares them with casting and the table denies it.

Where the refutation already was

Part 1 of the same brief carried a box, added the night before and correct: one of the enchant site's two tags carries a leading space and is tagged with the offset of the one without a leading space. That was a transcription slip in the decompilation, found and recorded properly.

Follow it through. If the second tag is really the leading-space literal, then the only row in that file whose bytes match it is casting's own later-syllable row. So enchanting's sequence is not two copies of one row; it is the same pair casting uses.

The correction determined the table's second line and the table was never revisited.

The rule that follows

  • When a correction goes into a document, search that document for what the correction changes. The expensive case is not the wrong sentence. It is the right sentence sitting two sections away from a wrong one that it silently fixes.
  • A reader believes the table over the prose, because a table looks measured. So a correction that touches a table has to reach the table.

And how it was actually settled

Not by argument. All 17 literals the four sites print were resolved through the exported table to positions in the owner's own executable and compared as bytes. 

pairs compared                   136
pairs identical                    2

Both of the two are a syllable format matched across the two modules. Every other pair differs, including every pair the brief had left open.

So the finding survives and its reason changes: the four sites share the walk over a spell's letters and the syllable formats, and nothing else. Only the walk is factored out.

My fourth absence claim, failing a new way

The brief said nothing in this project touches the three unbuilt sites. One of them was already half built: the charge that enchanting writes into a staff.

This time the search was run and it was too narrow. I grepped for what those sites print rather than for the sites. A narrow search and no search fail identically, which this project already says about searching the decompilation and evidently needed saying about searching itself.

And one thing the brief had no idea was there

Using a staff reads the staff's first content, not its first charge. The helper it calls applies no type test, while the call site's own comment says it takes the first charge.

So a staff holding something else first would have that thing's quality read as a spell number.

The reachability was measured rather than assumed. A staff is not in the original's own container type list, so the move command refuses to put anything into one, and the only thing that reaches a staff's inside is the charge enchanting gives it.

That is why it went in the anomalies section and not the confirmed bugs: the divergence between comment and code is real, and no reachable input exercises it. It is imitated, with no guard, because a guard would be dead code reading as evidence that the original checks the type. What was not checked is written down too: whether some other code path hands a staff something else.

Up next

The eight reagent names, which are the one thing the spellbook page still cannot print: it carries a bit number where the original names a reagent. The names are already read out of the owner's executable and cross-checked; what is missing is carrying them through the export, which is a format version bump and therefore a set of checksums that have to be found by failing rather than by guessing.
