Two Helpers, Five Quiet Differences

SPELL_CastMass and SPELL_CastField look like the previous slice's SPELL_CastMissile at first glance: a prompt, a halo, a shot, a failure path. Five exact points differ, and those five are exactly where a merged port would go wrong without noticing.

Five points a merge would break

The prompt is a third one, not either of the previous two: message index 10, where the last slice measured 9 for an actor target and 8 for an object target. The select range is never set, not conditionally as in the missile cast but not at all, so the cursor is not bounded by the spell's own range. The empty-selection test reads only the coordinates, not the selected object, so a location spell aimed at an empty square proceeds rather than stopping there, which is the whole point of a location spell. The shot flies at a hardcoded range of 8, not the spell's own. And a shot that misses prints message index 4 unconditionally, where the missile cast would choose between 3 and 4 by a range test. The same number, two different meanings: "missed, for any reason" here, "stopped short but still in range" there. That last difference alone is why the miss path is not shared with the missile cast, even though the rest of the sequence is: U6SpellLocationCast.Locate consumes slice C0's own missile trace rather than recomputing it, and both helpers build on top of it.

An explosion that succeeds quietly

Nine area effects share one per-victim loop, and eight of them print the success message no matter what they did. The ninth, the explosion, does not. In the original, SpellResult = -1 is assigned inside the loop, and only the explosion branch ever assigns it; after the loop, the success message prints only when that assignment never happened. An explosion that touches nobody never makes the assignment, so it prints success completely normally. An explosion that touches anybody at all silences itself entirely. The intuition runs exactly backwards: silence does not mean "nothing happened", it means "something happened and the original kept quiet about it". Four of the other eight effects, mass awaken, mass protect, mass curse and mass invisibility, are now built by setting a status bit; five shared routines, sleep, dispel, charm, kill and fire damage, are waiting for their own named refusal in the next slice.

A field exists before it is tested

The four field spells, fire, poison, sleep and energy, create the field object at the stop point first, and only test the square afterward. If the square refuses, the object just created is deleted again. The outcome looks the same as if the square had been tested first and the object never created at all, but it is not the same order, and this project reproduces the original's order rather than only its visible result.

Ten of sixty four, and neither half is enough alone

Who cannot be made invisible: ten of 64 creature classes, by two separate rules. Six classes are caught by one comparison, at or above the giant scorpion's own type number, the same comparison the multi-tile head resolution uses. Four are caught by name: the dragon, the hydra, the silver serpent and the slime, all below that type number. A port that kept only the four names would lose the six; a port that kept only the comparison would lose the four. The count is run over the 64 exported classes, not written by hand.
