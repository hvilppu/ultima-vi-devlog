A pool that never gave a slot back

M14's slice F9, and it is this project's own fault, not the original's: slice F6 wired eggs to hatch as the party walks, and that slice's own brief never once mentioned the routine that undoes the result. The owner found this in play. Pressing the F9 development key spawns a creature; after walking about twenty squares it refuses, "all 32 temporary slots are already taken." Once the pool is full, no egg can hatch either, and the world quietly stops producing creatures for the rest of the session.

Every creature takes a slot, and nothing gave one back

A temporary creature, a hatched monster included, lives in one of 32 slots this project has always kept at a fixed size. Nothing in this project ever freed one. Walking crosses the loaded area's own boundary every eight tiles or so; each crossing sweeps for eggs and hatches whatever is willing to, and after a few crossings the pool is simply gone. The development key is the loud half of the symptom. The quiet half is worse: once nothing can be created, an egg that already hatched stays hatched forever, because nothing ever clears that bit either, so every egg in the game can fire exactly once per save.

Two halves, read straight out of object.c

The original's own counterpart is OBJ_PurgeFarLocals, and it had been named as missing in four separate places in this project already, once in the character data, twice in the object world and once in the creature generator, each one a comment left behind by an earlier slice saying the purge did not exist yet. It has two halves. The first deletes every temporary actor, slots 0xe0 to 0xff, that is both far from the centre and carries the local bit. The second walks the whole object chain: a far map object that is local or already shapeless is deleted outright, and a far egg that has already hatched simply has its hatched bit cleared, so it gets a real try the next time the party walks back within range.

The window is forty tiles wide and deliberately not symmetric

object.c's own four inequalities read x - 20 > objX || x + 20 <= objX || ..., which keeps everything from the centre minus twenty up to but not including the centre plus twenty. An object sitting exactly twenty tiles east of the centre is far; one sitting exactly twenty tiles west is kept. The obvious symmetric reading, treat both edges the same, is wrong on one side, and the test pins both edges separately for exactly that reason.

Centred on the area, not on the party, and run before the sweep

Two details that would have been easy to get backwards, both read straight out of map.c. MAP_BuildArea calls the purge with the loaded area's own centre, its own origin plus twenty on each axis, never the party's own square; the two differ by up to twenty tiles as the party crosses a forty tile area. And it calls the purge before it ever hatches that area's own eggs, not after. Freeing a slot after a sweep has already found the pool full leaves that refusal standing until the next area change; this project's own walking step now calls the purge first, on the same aligned area boundary that already gated the hatch sweep.

A delete's own spilled contents get the same test immediately

Deleting a container spills what it holds onto the square the container stood on, which is still inside the purge's own far window. If what spilled is itself local, it needs the same delete, cascading through a chest inside a chest exactly as far as the nesting goes. The original's own walk resumes from the one id its delete just spilled rather than the id it had already queued up next, because the chain moved under it. This project reaches the same outcome a different way: the purge recurses straight onto whatever a delete spills, so every object a single call touches gets the identical test before that call returns.

What this does not do yet

A multi-tile creature's extra map tiles, a dragon's wings or a hydra's eight bodies, carry no containment link back to the head actor at all: the original finds them with a spatial search around the head's own square, OBJ_MoveCreatureParts and OBJ_MoveSerpentBody, and neither is built here. The head is purged the same as any other temporary actor, but its extra tiles are left standing on the map, orphaned. Named rather than silently dropped.
