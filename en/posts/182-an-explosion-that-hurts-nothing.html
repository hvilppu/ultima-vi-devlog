An explosion that hurts nothing

The cannon fires, the ball flies, and where it stops it explodes. I assumed the explosion damages what is around it, because that is what explosions do. It damages nothing. Explosion returns a list of what it touched, and the cannon's routine never reads it: the only damage is one roll of 1 to 60 against the thing standing on the impact square. 81 of the 85 usable types now reach their own handler.

The frame is the direction, and the table is a different table

A cannon's own frame says where it points, and it has a four-entry table of its own: frame 0 north, 1 east, 2 south, 3 west. This project already has an eight-way table, and the temptation is to use it. Counted: only frame 0 agrees. A port that reused the navigation table would fire frames 1 and 3 diagonally and frame 2 east instead of south, so three of the four would be wrong.

I wrote "two of the four" into the class's remarks first, and the test refuted it. That is the third time in this batch that one of my own counts failed its own test, and all three were the same kind: a number that felt obvious and had not been measured.

The aim goes past the barrel

The ball is aimed at the first actor within five squares. An object in the way does not stop the aim, so the ball is aimed past a barrel at the creature standing behind it, and whether it gets there is the flight's business rather than the aim's.

And when no actor is found, the aim distance is six, which is the loop variable's own value after it runs out rather than any square the scan looked at. The range is five. So a shot into empty air never arrives even over completely open ground, which means it always explodes, and the explosion is the cannon's ordinary outcome rather than its exception.

The impact square is the obstacle's own

When the ball does not get there, the original advances the stop position one more step, draws the explosion there, and only then asks what is standing there. So the damage lands on the wall or the creature that stopped the ball, not on the last free square. A port that exploded on the last free square would damage empty air, and it would look exactly right.

Two gaps, each one call wide

An object victim takes nothing, because the damage routine's own object branch (a breakable loses quantity points and breaks at nought) is not built here. The shot still reports the victim and the damage it rolled, so the gap is one call wide rather than a missing rule.

And the ordering question is a fourth instance of the same one: a square's contents can be read objects-first or actors-first, and the cannon asks twice, once for the aim ("is this an actor") and once for the impact ("is this anything"). This project chose objects-first at the explosion's own site, and the same choice is here for the same reason: it over-applies the rule rather than deleting it.
