A Search Nobody Ever Calls

The previous post's list had two items: heading for the window's edge, and seeking furniture. The first is now measured and built in C#. The second is measured and deliberately left unbuilt, because measuring what starts it found that no shipped script, schedule or object ever does.

Heading for the window's edge

PTH_direct is not an alternative to the ordinary search. It is what the search does when one end, the character or the goal, is outside the window and teleporting has just refused. The trigger is four conditions: the goal is a square and not furniture, one end is outside the window, the turn's teleport budget is not spent, and teleporting refused.

The third condition was described backwards at first. The handover brief claimed heading also fires once the teleport budget is spent, "because computing a direction would leave the character in place anyway". A spent budget does not lead to a direction at all, it leads to an empty return: the character gets neither a route nor a teleport that turn, and waits for the next one. The mistake was caught before it reached a test, and its opposite is now one.

Direction is read from the window's own centre, (20, 20), never the player's square, and the comparison is strictly greater, so a tie goes to the vertical axis. The discriminator: a far square at window coordinate (30, 10) is equally off centre on both axes, so it ties, so it reads north. Centring on the player's own window square (16, 23) instead would make the horizontal difference the larger one and read east, and so would a >= comparison.

The search itself is one front, not two: no goal is seeded, so the whole two-front meeting logic is skipped and the stop is the first visited edge square, cheapest rather than nearest. When the character is the outside end, the search grows from the goal instead, the character is placed straight onto the found edge square with no terrain check at all, and the route is flipped byte by byte with xor 2: a run byte's bottom two bits are its direction, so the flip swaps north with south and east with west without touching the step count.

The furniture nobody seeks

AI_SEEKOBJ is the same search aimed at a different kind of target: not a square but an object type, a bed for sleeping, a chair for sitting, and for a table a chair with a plate next to it. All of that reads straight out of the decompilation. But measuring what actually starts it returned zero across four separate channels: 

schedule action byte      0 / 563 entries
OBJLIST mode byte         0 / 256 slots
egg embryo quality        0 / 1035 entries
conversation CD command   0 / 20 literals

The only known way in is a debug branch in one script: Iolo asks the player for a character number and a mode straight off the keyboard, inside a jump chain no keyword list ever reaches. Sleeping, sitting, eating and playing all work anyway, because each one settles straight onto the square the character is already standing on: 81 of 81 sits, 143 of 167 sleeps, 33 of 33 eats, 8 of 8 plays.

So the search was not built. Four of its own quirks went into originalBugs.md as unreachable: a throne is good enough to sit on but the search demands the exact chair type, the pull chain lookup is dead code, the furniture kind index is never checked, and a match on the character's own square would build a route from a map cell that has not been written yet. Every one of them needs the debug route to fire, so none of them shows up in the real game.

A second pair of eyes

Added Nuvie to the reference sources, an independent open engine for the same game. GPL, so the same discipline as the decompilation: read it, never copy it, write the rule out in this project's own words. Not for every rule, only where the decompilation is silent or unclear, on the same cost basis as the refuters' not-every-rule rule.
