The greeting that was empty

The last post ended by naming three things, and all three are built now. A conversation greets you with the right form of address, a townsperson walks over and starts a conversation of their own accord, a brawler's fist flashes a tile over its victim and wakes a sleeper, and a restore no longer lands on a spellbook page over a freshly loaded party. The interesting part is none of those four. It is that three of them were found by counting consumers rather than by reading a rule, and that twice the count refuted something I had just written myself.

Eighteen variables, of which two were seeded

The original sets eighteen variables when a conversation starts: four strings and fourteen numbers. This engine set two of them, karma and the Gargish flag. A comment named the gap honestly but did not give its size, and when I wrote the size in, I got it wrong three ways: fourteen instead of eighteen, four instead of six, and three variables missing from the list altogether. The count had been made by eye off a routine that was open in front of me.

The right way to decide which of the sixteen to seed is not to read the routine but to count the readers. The owner's own converse.bin holds 199 scripts, and a script reads a variable two different ways: in an expression and in printed text. Both channels counted: 

$G  form of address        197 reads   64 scripts
$N  NPC name buffer        124 reads   53 scripts
$T  part of the day         65 reads   49 scripts
#W  the NPC's work type    110 reads   47 scripts
$P  party member's name     55 reads   36 scripts
#G  gender flag             49 reads   22 scripts
#O  party size less one      7 reads    4 scripts
#H  the hour                 6 reads    4 scripts

#A #E #I #P #S  the member's five statistics   0 reads   0 scripts
#D #M #Y        the date                       0 reads   0 scripts

So 64 of the 199 scripts greeted the player with an empty word where the form of address belongs, and that is the first thing a player meets in their first conversation. And the member's five statistics, which I had named as the slice's own prerequisite, interest not one shipped script. What they read from the member is one string, their name.

The four strings are the original's own text and do not enter the repository. They resolve by module and offset out of the exported message table, and I checked all six rows before a line of code was written: each offset holds exactly one entry, and the text lengths are 6, 6, 39, 7, 9 and 7, which match the decompilation's own words. The length is the discriminator.

And a crash turned up on the way

The conversation world has a clock field that Rest() needs. That field had no production writer at all: the only writers anywhere in the tree were test files, and Rest() throws without a clock, by its own design. The shipped scripts hold 18 rest instructions across 16 scripts, so the first innkeeper who offered a bed would have crashed the conversation. The view sets the clock now at both places where it builds the conversation world.

That throw was not the defect. It was the one thing keeping the gap honest: had the field quietly skipped the hours instead, the innkeeper would have healed the party for free and nothing would have said so.

A townsperson comes to you, and names the wrong member

The schedule has a converse behaviour: a townsperson walks up beside the nearest party member and starts a conversation. The arm was built and its delegate had no caller, so the townsperson arrived and stood there. Now it talks.

The interesting part is which index it passes. The original's helper passes the nearest member's character number into a parameter that means a party slot, and the decompilation's own comment flags it. I measured out of the memory layout what that reads: the name array holds sixteen rows, so a character numbered 1 to 15 gives another member's name, and a character numbered 16 to 34 reads the dexterity array as text, because that array begins immediately after the names. The starting party is characters 1 to 4 in slots 0 to 3, so it is off by exactly one: a conversation begun on the Avatar's behalf gets the second member's name.

This is reproduced rather than fixed, like every fault of the original in this project. Correcting the index passes every other test and fails exactly the one written for it. For characters 16 and above the dexterity array cannot be read as text here, because this project does not have that memory layout, so it answers the empty string and the divergence is recorded where it arises.

A fist that flashes and wakes

The original's hit flash is a shared primitive: fifteen call sites, five of which this project's own files named as a gap. Its four rules sit at three different nesting depths, and the depth is the whole measurement:

  • the tile and the sound need both the flash flag and the eleven-square window
  • the hurt-this-turn bit needs the flag alone, so an off-screen actor still gets it, which buys it one turn of immunity from the ground it stands on
  • the waking is outside both, so a suppressed flash still wakes a sleeper and restores its original shape
  • the flag re-arms itself at the end, so a suppression covers exactly the next call

The flash's duration was measured from the sound rather than written as a frame count. The original plays the sound between two redraws, and that call is the only thing in the sequence that waits, so the flash lasts exactly as long as the sound: effect 4 is 800 draws at 82 microseconds each, which is 65.6 milliseconds. The test computes that from the sound renderer and compares it against the constant, so the constant cannot fall behind.

And the flash draws through the composer's own object-tile path rather than painting the screen, so it inherits two refusals for free: a hidden cell and a dark cell draw nothing. That was not invented but read out of the original's own drawing routine, whose own header names hit effects as the only reason its "on top" mode exists.

A restore that forgot four of its own resets

Ctrl+R loaded the saved game but left the status view, the status member and the select mode alone, the last of which is two targeting flags here rather than a stored field. So a restore could land on a spellbook page over a freshly loaded party, and Ctrl+R pressed with a target prompt armed loaded the save with the aiming cursor still up.

The branch worth pinning is not that Y resets them but that N changes none of the four, and that cannot be asserted from a test which has to construct a Unity view. So the decision is its own type in the engine assembly, and the build run proved it by breaking it: hoisting the reset above the Y/N branch failed all six tests. The party view is also entered rather than restored from the stash, because the original sets the display, and a stash-popping build would bring back whatever a spellbook browse left there.

The slice also corrected a claim in our own code. The restore command's remarks said the status steps were already handled elsewhere, on the strength of the panel having arms for them. The arms exist and nothing called them. "An arm exists" and "the step happens" read identically and are not the same claim.

What the counting cost and what it bought

Three times in this batch a count refuted something I had just written. A comment said fourteen where the number is eighteen. A brief said the converse arm needs the nearest member's party slot, when it needs the character number in the wrong parameter. And a brief said five dead refusals behind solo mode, when there are six, and the sixth is the only one in the list that draws.

The same counting found one thing that is my mistake rather than the original's: originalBugs.md numbers its last four entries from 2.30 again, where the numbering otherwise runs to 2.83, so nine citations in code, tests and documents point a reader at the wrong entry. It is recorded as a debt to be paid rather than as a bug of the original's, because it is not one.

The numbers were run after each slice separately, with nothing skipped: six build targets with 0 warnings and 0 errors, CheckAsmdefs.ps1 with 0 broken references, and the leaked-text check with 0 findings. One of these changes what appears on screen, the hit flash, and that half has not been seen: the engine's rules were proven by breaking them nine ways, but a tile appearing over a brawler's victim is something only a screenshot can prove. Unity's own editor Test Runner was not run.

Next

The number keys do nothing in the game, and that is measured rather than a matter of taste: solo mode cannot be entered because only tests write that field, so six built and tested consumers are live code behind a constant. And the hail storm's animation turns out to be a correctness slice rather than a decoration: the original rolls dice inside the animation, hundreds of them, and this project has exactly one random stream.

A personal project, built from a purchased copy of the game. No game data is distributed here or in the repository.
