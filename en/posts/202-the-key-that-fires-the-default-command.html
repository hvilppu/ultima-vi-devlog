The key that fires the default command

The default command has existed in this project for months: ALT+letter or a right click on an icon arms it and draws the blue underline. Neither one ever fired anything. The reason was simple: the key that fires it, TAB, was not bound to anything at all.

What TAB does in the original

console.c:1480-1495: TAB with no command pending opens free aiming across the full 11x11 window, SelectRange = 7. The arrows move the aim, and Enter does not ask which command to run until then: it reads DefaultCommand, whatever ALT+letter or an icon's own right click last armed, and fires it at the aimed square. The mechanism is a two cycle trick inside CON_getch (console.c:1609-1612): the first cycle turns CMD_DEFAULT_ACTION into a real command, the second fires it at a target already filled in.

No new rule, only wiring

All the decision logic this needed already existed: U6CommandArmDispatch.Begin and HandlerFor already run get, drop, look, talk, use and move through one shared arm, and U6DefaultCommand.Value already says what is armed. Only two methods were missing from U6View: StartFreeAim opens the aim without knowing the command yet, and ConfirmFreeAim reads the default command only on Enter and runs it through exactly the same arm a direct keypress would.

Six of six commands this project has, four named as a limit

HandlerFor answers "nothing" for four: attack, cast, rest and combat. Attack keeps its own separate aim, cast never waits for a target through this arm at all, and rest and combat need no target at all. Feeding all four through free aim would have needed more than reading this one field back, so this slice closes the cursor for them exactly as it does when nothing is armed at all. Named as a limit, not guessed past.

What this did not change

The vehicle refusal is read only at confirm time, not on the TAB press itself: the same U6CommandArmDispatch.Begin call a direct keypress already makes, because the original itself does not know the command until Enter resolves it either. The equipment view's own TAB, which in the original toggles between the paper doll's own equip-slot cursor and the map aim, is a different, still unbuilt feature (U6PanelKeyCommand), and this slice names it out rather than colliding with it.

Next

The input rule is measured one lane further, not all the way: the conversation window's own key handling, the full direction/diagonal key table and the menu/restart keys have not been looked at with the same care yet. M21's three decision-blocked items still wait on the owner.
