A name that said needs

The spell family called MagicalHalo has eight cases. Six wrote a duration, and two were named refusals: one needed the gem command, the other needed a location print. Both have been built along the way, so both cases run now. Peer shows the map, locate prints the position.

An enum whose name went stale

Those two cases were modelled as an enum whose values said what each one needs: NeedsGemCommand and NeedsLocationPrint. That was honest for as long as neither existed.

Both exist now, and at that point the name is the same rot this project keeps finding in comments: a claim about an absence that nobody goes back to update. An enum is no different from a comment. It is a tail now rather than a refusal, and its values say what the case does: show the peer map, or print the location.

Peer's row is printed after the key

The original calls UseGem(0) and then prints the row. And UseGem waits for a key, because the map is on the screen. So the row belongs after the key, not under a map the player has not dismissed yet.

This project cannot block, so the map is a sub-mode and the row is carried across the wait in a field of its own. A small thing, but it is exactly the place where "a sub-mode instead of blocking" would quietly reverse the order if nobody noticed.

Three counts moved

outcomes that declare an exported row      16 -> 17
outcomes that print this project's English 12 -> 10
outcomes the caller formats                 0 -> 1

The last is new: locate's line is four exported rows with two numbers between them, so it is neither one row to resolve nor a phrase this project invented. The list of status sources gained a fifth value for it, and the line builder refuses it the same way it refuses an outcome the original prints nothing for.

The formatting already existed: the sextant prints the same position from the same reading. That was the second consumer the reading's own remarks named, and now it is two consumers rather than one and one named gap.
