Four Behaviours and One Nobody Measured

The icons came alive. Alt and a letter, or a right click on an icon, arms a command and a blue line appears beneath it. But the interesting part was a fourth rule nobody had measured, found only by reading the press edge to the end.

The press edge has four behaviours

Three were expected: the first poll with a button down is the press, the ones after it are not, and releasing clears both.

The fourth was written down nowhere. While a button is held, only the command the press itself produced repeats. Drag the pointer into another zone while holding, and the command computed there is computed and thrown away. Nothing happens until the button comes up.

It is one line, and it is what lets a held direction walk without the pointer wandering onto the icon strip and firing something else. Without it an implementation would look like it worked and behave wrongly exactly when the player moves the mouse while walking.

Both halves are asserted, for a concrete reason

The suppression can be implemented wrongly in two ways, and each would pass half the tests. Suppress everything while held, and "a different command is suppressed" passes. Let everything through, and "the same command repeats" passes.

The build broke each separately and each failed its own test. That is a different thing from one test that happens to cover both.

And one decision is design rather than measurement

The original paints the underline when the state changes: erase the old, draw the new. This project composes the whole screen every frame.

So the state answers what is armed now, and the row is painted every frame. Same result on screen, different mechanism, and it says so in the code. This project has learned the hard way that an unmeasured choice dressed as a measurement is worse than a hole with a name.

The safety net had to grow, and that is where I was careful

New code needed a type through a package assembly and hit an old conflict between the monolithic engine facade and the real modules. The check projects moved to the modules.

This project has been burned four times by a check that covered less than it claimed, so I did not take the change on trust. I removed the module references on purpose: 74 errors. The references are load bearing and the check still fails when it should.

But the change brought a dependency that was not there before: one project now references an assembly Unity itself compiles, under a gitignored directory. A fresh clone does not have it, and the check would have failed with a confusing missing-file error.

It now has a guard that says plainly: "nothing was checked, and that is not a pass". The same words the leaked-text check uses, and it was proved by making it fire. A new check is proved by breaking it, because reading one is not evidence that it works.

What a player sees

Only in a special case. Alt and one of ten letters, or a right click on an icon, draws a blue line under that icon, and another combination moves it. Nothing runs a command yet, and a left click works as before.
