A Number That Decided the Shape

Two slices, and in both the search came before the building. In one, a number decided the whole shape of the slice before a line was written. In the other, it found an answer I had just written down as not found.

550

The next piece was the selection: what the pointer is pointing at, which commands then use. I meant to measure it and build it.

First I swept the name. 550 hits in the source directory, 555 across the tree.

That number answered a question I had not asked. A thing with five hundred and fifty readers is not a slice, it is a layer. Every command handler, every targeting path and most of the status panel reads it, so giving it a home here would have been an architectural commitment nobody has made.

The bounded part was the routine that fills it: 14 hits and one function. That was built. What it fills was left homeless on purpose, and the brief says so outright.

And that routine holds something tidying would lose

It tests one threshold, not the zone table. It never re-tests the map rectangle and never consults the zones, because every caller is already inside a zone arm that decided.

The build replaced the threshold with a zone lookup to see what happened. The test failed, and took two others with it. That is the fix anyone tidying the code would make, and it would answer differently for a pointer the original never asks it about.

And my brief asked for something impossible

I wrote, as a discriminator: "a point the zone table would call the panel, but whose x is below 168". The panel zone's left edge is 168. No such point exists.

The build said so and used the case that is constructible. It did not invent something to fit my wording, which is the thing you most want from an instruction when the instruction is wrong.

The second slice: the letter that confirms

Pressing the pending command's own initial turns the key into enter. For eight of the ten commands: rest and combat are absent. And cast carries an extra condition the other seven do not.

Both ways of getting that wrong failed under test: adding rest and combat to the list, and applying cast's condition to all eight or to none.

And the gate fired again

My brief said: "the select mode's value two has not been seen, and the sweep is where it should turn up."

The sweep found all four values enumerated in the original's own comment, one grep away. None, the aiming cursor on the map, the slot cursor in the equipment view, typing an incantation.

That is the darkness shape again, smaller. The answer existed and was written down, and the search had not been run. The difference is that this time it surfaced before the building, rather than by playing months later.

And one number out of 81 is worth more than the rest

The select mode has 81 hits. Six are already built here under other names. Seventeen are named as gaps by this project's own briefs.

54 have never been opened.

That is the number I want. It does not say anything is broken; it says how deep one name runs and how much of it is still unasked. The difference between assumed-finished and never-opened is where this project's most expensive mistakes have all lived, and now that difference is a number rather than an impression.

Up next

Four rules now stand complete with no caller, and that is a named state rather than an accident: the pointer's zones, the armed default command, the dispatcher's arms and the selection's filling. What would connect them is the selection itself, which has 550 readers and no home yet.
