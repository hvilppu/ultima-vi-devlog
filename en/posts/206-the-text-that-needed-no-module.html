The text that needed no module

M20's third piece: the ending's own 16 text pages, which carry not one offset comment in the decompilation, unlike every other module this project has measured. The offsets turned up by searching the owner's own END.EXE directly, and it turned out they never need a module base at all.

50 strings, 45 came back unique

main.c's own ShowText builds each page out of several TXT_sappend calls. All 50 of their own strings were searched for, as raw bytes, against the owner's own END.EXE, from a scratch-only script that is not part of this repository. 45 came back exactly once, in one contiguous string table. The remaining five are page 15's own connective words, "and " and the like, which land elsewhere in the file by coincidence and need no unique offset of their own.

No module at all

Every other piece of text in this project is read out of GAME.EXE as a module base plus a relative offset, because GAME.EXE is a wide collection of decompiled modules. END.EXE is one 40112 byte file with no such structure: every measured offset is a direct byte position from the start of the file. The whole module-base search every other text needs on the GAME.EXE side falls away here entirely.

A discriminator out of the chain itself

The 45 fragments sit in one contiguous run: each one's own end plus one terminating byte is the next one's start. 43 of 44 gaps hold (the one exception, spanning page 15's own dynamic middle, is named rather than counted). Being contiguous does not by itself prove the offsets are the right ones rather than some other chain's, so the reader re-runs the measurement's own uniqueness search against the real file every time the pages are loaded.

The edges built, the middle left open

Pages 0 to 14 are fully done. Page 15, the played-time congratulations line, is only partly built: its banner, opening sentence and closing sentence are read, but the actual "in two years, three months" clause needs a word table and the conditional logic the five unmeasured fragments carry, plus which GAME.EXE field the played time actually comes from. Named open rather than guessed at.
