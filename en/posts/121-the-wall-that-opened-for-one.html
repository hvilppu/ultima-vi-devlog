The wall that opened for one

Five spells have been waiting on three missing inputs in the missile family's own switch, each one measured and built but unreachable from the spellbook. This is the first of five rounds that opens the wall one target at a time, and the first round found something other than what it went looking for.

Three inputs, five locks

The missile family's own effect switch is built to take further inputs as optional parameters as new spells have needed them, and five earlier spells are already appended to that same signature this way. The five remaining targets need three things the view has carried all along but which have never reached the switch: a tile bank, the base tile table and the creature class table. Once all three were appended to the switch's signature the same way the earlier five were, the path opened for all five at once. What did not open is the wiring itself: that happens one target at a time, across five rounds of its own, so one mistake has exactly one place to live.

Vanish first, because another spell is waiting on it

Of the five targets, vanish goes first, and the reason is not its number. The reappear spell has existed and been tested in the engine for two slices now, but it has never been able to succeed in the game: it reads a shared memory word that vanish writes, and because vanish had no path from the dispatcher to its own routine, that memory was always empty. One wire unblocked two spells. A test now runs the pair end to end for the first time, vanish then reappear, through the live dispatcher, neither one taking a named refusal.

A finding that had nothing to do with this round

While wiring vanish, something older turned up: the view had never passed a visibility test to the missile switch, even though the chain bolt arm requires one. Chain bolt has been wired and working for two slices. In practice this meant that chain bolt cast from the spellbook threw an exception instead of casting, every single time. The fault is not this round's doing, only this round's finding, made while working on something else entirely, and it has been reachable by a player for the whole time since chain bolt was wired.

The reason no test had caught it is simple: the engine side tests called the switch's own method directly, with named arguments, rather than through whatever the view would actually supply. The two sides, the test and the real use, were measured along two different paths, and it was the second path that was broken.

A fix, and the test that would have caught it first

The fix itself is one line: the view's own call site now passes a visibility test to the chain bolt arm. Alongside it a new test runs all nineteen cases built so far through the view's own, full set of inputs and asserts that none of them throws for want of an argument. The test was proved correct the way this project always demands when it can: it was run first against the fault, and it failed at exactly that one arm, 0x60, and nowhere else. The other eighteen closures built the same way were checked with the same test, and none of them carried the same gap.

The fault is this project's own, not the original's, and it is recorded as such: a wiring mistake made here, not an imitation of the original's behaviour.

Four rounds left

Of the missile family's 23 targets, 19 are now built and wired, not 18. Dispel field, animate, clone and replicate are still behind the wall, each getting its own round from here on, one at a time, in number order, since none of them waits on another the way reappear waited on vanish.
