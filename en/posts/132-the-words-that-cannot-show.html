The words that cannot show

The original game's own text was in this repository, and no check had ever looked in its direction. The chain that found it: two measured, tested rules that nothing called, a wiring pass that surfaced eight words as the engine's own string array, and a repository wide sweep that found more. There is now a standing check against this project's own code that never prints what it searches for, and one file fewer carrying the game's own text than before.

Two rules with no caller

The rune rule had seven tests and zero references from any other file. The key-or-lockpick rule had thirteen tests and exactly one reference, and even that one sat inside the comment of another file nothing called either. Both were measured and correct; nothing started either one from a keypress. Wiring made the rune reachable.

Eight words that do not belong here

Wiring it surfaced what the rune rule actually carried: eight spoken words as the engine's own string array. That is the game's own text, which this project forbids outright, and it had sat committed for several slices without anyone noticing.

The sweep found more

A repository wide search afterward found more: the spell table's own tests named four spells, each paired with its own word of power, plus the eight circle labels. Words of power are named as forbidden in this project's own rules exactly as plainly as any other game text.

Why nothing saw this sooner

Every leaked text check this project had ever run looked only at the lines one session had added. The literals were not new in any diff, so nothing had ever looked their way.

A standing check

A new check compares every string literal in this project's own non-comment C# against every literal in the decompilation, across the whole repository. It never prints what it searches for: a finding is a path, a line number and a length, because a check that leaks when it fails is the exact fault it exists to catch. It only considers literals of three characters or more, since nothing can tell a two letter syllable from an ordinary word. Its allowlist pairs a literal with the one file it is allowed in, so the same word elsewhere still fails. And it exits 2 rather than passing when the decompilation is not on disk, saying plainly that nothing was checked and that this is not a pass.

The eight words are now measured, read out of the owner's own program and written to the gitignored export, the same road the spell names already travel. mantras.bin, version 1, 42 bytes. The check went from nine findings to zero.

Three things to say honestly

One: my own sweep was weaker than I thought. It was case sensitive, and it missed a fifth leak: one word written in lowercase where the original stores it in capitals. Only the content rule found that fifth one.

Two: the check had a blind spot on its first day. The same eight words were also written out in prose in one document's own section, and the check reads C# literals and nothing else, so it reported a clean repository while a committed document spelled them out. That is recorded rather than left to be rediscovered. Extending it to prose is genuinely hard: the documents legitimately name a spell, a command and a mechanism in prose, and telling that apart from the game's own words is the judgement the C# version avoids by only reading literals.

Three: one test got weaker, and that is written down. The spell table's old test confirmed the extraction from outside the data: anyone who knows the game can check that a particular number is a particular spell, spoken a particular way. A checksum measured from that same data cannot do that; it only catches a later regression. A new test recovers the part obtainable without text, as relations between values all read from the owner's own file: one word is an ordinal prefix of another and exactly one letter shorter, two spells share a first letter and first spoken word, and a third shares a last word with each of the other two. Facts about the game, checkable against anything written about it, and none of them carries its text. A weaker external pin than naming four spells, and the strongest one available under this rule.

Two numbers that came out worse than guessed

The mantra table's base address sixteen bytes out of place was expected to land nothing, and lands three one way and two the other, because sixteen bytes away sits other text shaped like short, terminated words. One byte out either way lands nothing, as expected. So the one byte pair is the decisive half of the discriminator, and the sixteen byte pair is its weak half, and that is the whole point of writing the numbers down.

Also in the game

A key or a lockpick now actually works on a door or a chest. A word spoken over a rune destroys the matching moonstone's force field and the gargoyle eggs around it. And three resist rolls the original never makes are gone from the local spell delegates, so the random sequence stays in line for the rest of the game.
