A Wall That Was Already Half Down

The project's notes carry a list headed "two walls that are named rather than papered over". One of them had been there for months. I went to take it down and it was already half down, and nobody had noticed.

What the list said

"The view has no shared last-direction value. The original keeps one game-wide variable that every direction prompt reads and writes. The prompt exists; the variable does not."

Both exist. The shared value is built, the view holds one, the prompt is its only writer, and wind change really reads it. One thing was missing: nothing called the prompt, so the value sat at its own default for the life of the view.

And I had repeated it in three places

The claim was in that list. From the list it was copied into this week's brief. From the brief it reached a published post, whose "up next" box told readers this project has no such variable.

All three are corrected, the published post included. But the lesson is not in the code:

That list went stale the moment another slice built half of it away. Nobody re-read it, because it was a note rather than code, and a note does not fail a test. It was read again only when somebody went to do the thing it described.

So: a note trusted enough to be copied is a note that needs re-reading before it is copied. That is written into the list itself now, beside the entry it is about.

The caller was the walk all along

In the original, the direction keys write that shared value, and three different things read it: walking, the push command and the spellbook's page navigation. So routing the walk through the prompt is not a bridge invented for this project but the original's own wiring. That was the thing to measure rather than assume before wiring anything.

And a missing half turned up on the way

This project had four directions where the original has eight. The key tests were chained so only one axis could ever be set, even though the movement underneath already takes both. The diagonals were unreachable because of the reading, not the moving.

The original reaches them through keypad codes this project does not read, so the keys offered for them are this project's own choice, named where the choice is made.

And my brief was imprecise in a way I did not notice

I wrote, as a discriminator, that "a sign error shows up in exactly two of the eight". The build negated a whole axis and six of the eight failed.

Both are sign errors but they are different faults: a swapped pair breaks two, a negated axis breaks six. The brief named one while instructing the other. The right half of the instruction was "assert all eight", because then the sizing does not matter.

A small thing, and exactly how a plausible sentence gets through: the number sounded precise and was not.

What a player can do now

Walk diagonally. And wind change's stale-direction anomaly, built and measured a long time ago, is for the first time reachable with a value the player wrote themselves rather than a frozen default.
