Two Modules, One Strip

The bottom of the screen was entirely black. It now carries ten command icons and a date and wind line, which is what the original puts there. The interesting part is where the measurement came from: two modules that do not know about each other.

One strip, two independent sources

The startup code draws nine icons as consecutive tiles from x 8, sixteen pixels apart, at y 176, and a tenth, the combat toggle, at x 152.

In an entirely different module, in the mouse handling, there is a table of hit zones, and one of them is x 8 to 167, y 176 to 191.

152 is 8 plus 16 times 9, so those ten cells tile that zone exactly, with no gap and no overlap. Two pieces of code that never refer to one another describe the same rectangle.

The same happens vertically: the date line is drawn at row 21 of the full screen window, which is y 168, and the icons begin at y 176. Eight pixels, which is exactly one text row. The line sits directly on top of the icons.

So the tests assert the agreement, not the numbers

It would be easy to write four tests saying "the left edge is 8", "y is 176", "the row is 21". Each would pass even if one number had been copied wrongly, because nothing would compare them to anything.

Instead the tests assert that the cells tile the hit zone and that the line sits directly above the icon row. A wrong origin or a wrong stride breaks the first; a wrong row number breaks the second. Both were broken on purpose and both failed.

And not one word reached the source

The line's format is the game's own text, and so are the nine wind direction names. They resolve from this project's own export at runtime, the format by name and the directions by offset, and the tests assert them by length and by the row they resolve to, never by their words.

I measured the format's length myself before the build pass reported it. Both got 23. That is the whole idea of the rule: a number that can be checked twice without the text going anywhere.

One step past the brief, and it says so

The brief required only that the line's text be identified and its position measured. The build pass also implemented the console's own formatting routine, measured from that routine, so the substituted line could actually be drawn without the format string ever becoming a literal.

That is a judgment call rather than a measurement, and it is named as one. The grammar is the original's; only numbers and strings pass through it at runtime.

Three things are named rather than left looking decided

Nothing tracks a default command, so the underline the original draws beneath the chosen icon exists as a value with nobody to draw it. The combat toggle is always given its off state. And this project composes the screen every frame where the original drew the strip once: a difference in mechanism, not in what is seen.

All three are said in the code. An unbuilt thing that looks built is worse than an unbuilt thing with a name.

What is still missing from the screen

The border art, which is a loaded picture rather than tiles and which nobody has read. The map's own eight pixel margin. And rows y 193 to 199, which no measurement speaks for.
