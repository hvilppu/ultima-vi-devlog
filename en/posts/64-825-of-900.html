825 of 900

Six small routines several spells share: sleep, poison, the magic arrow, direct damage for three spells, charm and kill. Four of them use a resistance formula that looks familiar and is not: the last slice's three rolls were one formula, this is a second one, and the difference shows up in 825 of 900 measured pairs.

A formula that looks the same and is not

combat.c's own combat contest halves the target's figure and takes the caster's whole: INT(target)/2 + 15 - INT(caster) > 1d30. The last slice's three rolls quarter the target and halve the caster instead. Two formulas, both look like the same idea, and 825 of 900 pairs of figures from 1 to 30 differ observably in which one they give. The difference is not uniform: at equal high intelligence, 30 against 30, the combat contest never lets the target resist at all, where the other formula lets it resist one time in five. Against a strong target and a weak caster the order flips: the combat contest is then the harsher of the two. A port that shared one resistance helper between these two formulas would get four of the six effects wrong in 825 of 900 cases, and nothing would fail to signal it.

A caution that was not shared

Sleep and poison both read the same creature class immunity table, but only sleep checks first whether the class number is even valid. Poison hands the number straight to the lookup, whatever it is. Two routines, written minutes apart in the same file, one defensive and one not. The asymmetry is recorded rather than tidied away: nothing in this project lives at that memory address to be corrupted, so inventing a victim for it would be inventing behaviour rather than measuring it.

A charm that cannot be repeated

Cast charm on a target that is not charmed, and it gets charmed. Cast it again on the same target, and the charm ends. Nothing happens twice, no error message: the result is left untouched, so the cast reports plain success as though nothing special happened at all. This is the only way to end a charm on purpose, and a port that treated a recast as a no-op would lose it entirely.

A scratch that kills

Every other damaging effect in this slice tells a neutral target how much damage it took, and that number decides whether the target turns hostile. Kill does not. Kill always passes a constant one, whether the target had one hit point left or a hundred. Killing a neutral outright provokes it exactly as a scratch would, no more.

One hit point, not a bit

Disable sounds like a status effect, and it is not. It computes the target's hit points minus one and runs it through the same damage routine as harm: the same experience calculation, the same wound severity. The outcome is exactly one hit point left, reached by damage rather than by flipping a bit.

A number that got worse and was better for it

The measuring session's own figures claimed 14 of 64 classes immune to sleep, 3 to death and 4 to poison. Recomputed directly from the exported class table, the real numbers are 19, 4 and 6. The cause turned out to be the file format itself: a class's abilities are stored in a Traits field as text, and when every one of its bits matches a named ability the field prints the names comma separated; when a higher, unnamed bit is also set, it prints the raw number instead. Nine of the 64 classes print as names, and the original measurement only read the numbers, silently dropping nine rows while the denominator stayed at 64 regardless. Exactly the mistake this project has already made once before with a search that only matches digits. The corrected number looks worse written down, and it is the real one, and it is the one in the tests now.
