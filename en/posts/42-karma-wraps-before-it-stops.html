Karma Wraps Before It Stops

M17 opened with its two smallest pieces: the Gargoyle language flag and karma. Both were simple to build as they stand, but karma's own machine code turned up the same hole twice. That is not an accident: the original ships a correctly written version of the same calculation, and it is never called.

One variable remembers the game, the other does not

The conversation language has two lettered variables that come from game state, and they behave differently for no reason visible in any script. #K (karma) is seeded from game state at the start of a conversation but never written back, even if a script changes it mid conversation: it is a snapshot. #L (speaks Gargish) is seeded the same way but always written back when the conversation ends, even though no script ever changes it: it is a live connection that happens to do nothing right now. The split comes straight from the original's own TALK_initTalk, and this project was missing both sides of it: the temporary variables #0-#9 and $0-$9 leaked from one conversation into the next because nothing cleared them, and the seeding of the lettered variables did not exist at all. Both are fixed now.

Adding wraps, subtracting does not

Karma is an unsigned byte, and the opcode that raises it handles overflow differently from the one that lowers it. Raising computes the sum as a byte, so it can wrap around, and only clamps to 99 afterward. Lowering compares with a signed comparison and clamps to 0. The same game also ships a correctly written, uncalled function that would compute the sum as sixteen bits before storing it, where wrapping could never happen at all: it is just code nothing reaches. The path that is actually used is the one that wraps.

Pickpocketing forgets the clamp entirely

One spell lowers karma with a plain byte subtraction, with none of the comparison every other lowering path has around it. Karma 0 through 4 after a successful pickpocket becomes 251 through 255, not 0. Three statues in Britannia pick their closing line with #K / 30 and never check the bound, so wrapped karma reads straight past their script buffer. Neither is reachable in this engine yet, since there is no spell system, but both are on record: whenever spells arrive, this chain is already measured.

One of our own bugs found twice before it got fixed

The save's game state block was being exported as 386 bytes. The real measured length is 130, and the remaining 256 bytes are not game state at all but the next table in the save. This turned up independently in two separate measurements back to back, the moongate round and the karma round, and survived the first round uncorrected. The fix was a one line change in the export tool: read the measured length, not to the end of the file.

What stayed unbuilt

Virtues are not here, since they would be used by shrines and a plot state machine that do not exist yet. The Gargoyle language's own translation table is out of scope entirely: that is text data, not an engine rule, and text data does not belong in the repository.
