Combat does not break off anything

The plan's M16 carried a list headed "deliberately not built", with a reason beside each item. I read the reasons. All four were stale, and one of them was not stale but wrong.

The list, and what was left of it

Gate Travel spell     "no spell system"
                      there is: U6SpellGateTravelCast, wired to a prompt

solo mode refusal     "no solo mode in this engine"
                      there is: the number keys enter it

breaking off combat   "no system for it"
                      there is: M14 landed, AND THE DESCRIPTION WAS WRONG

red gate removal      "no system for it"
                      type known, destination table not exported

The one that was wrong rather than stale

"Breaking off combat" describes a behaviour the original does not have. The first line of the check is if(InCombat) return;: in combat the gate is not taken, and nothing is printed. A party fighting on top of an open moongate does not go through it and is never told why.

From the player's side that difference is the whole thing. "Breaks off combat" would mean the gate works and the fight ends. The real rule is that the gate does not work. The two would have been written as different code, and both would have looked sensible.

Three refusals, and their order is the measurement

1. combat     the square is not looked at, no line
2. vehicle    the square is not looked at, no line
3. solo mode  the line: "must be party mode"

The first two are silent and the third prints. That is why NotChecked and MustBePartyMode are separate outcomes even though the party stays put in both: only one of them says so on the status line.

And the solo refusal is per object found, not per square. The test sits inside the loop, after the type has matched, so walking around in solo mode prints nothing until there really is a gate underfoot. An implementation testing solo mode per square would shout the line on every step.

The ladder is not in the list, and our own enter key skipped the refusal

A step takes four types: the moongate, the red gate, the mine shaft and the hole. The ladder is not one of them: it has its own solo refusal in the use command, at a different measured site.

Which turned up a defect of ours. The same act sat behind two keys: the use command asked about solo mode and the enter key did not. So enter would take you into a cave in solo mode where the use command refuses. Two paths to one act, and only one of them had the measured refusal.

What is really left

The red gate's destinations. They are three tables in the owner's own executable, indexed by the gate's quality, with nought meaning "stay here". Nothing has exported them, so stepping onto a red gate has nowhere to send the party yet. The three refusals already cover it, because they are the same three for all four types.
