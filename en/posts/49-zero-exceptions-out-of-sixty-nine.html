Zero Exceptions Out of Sixty Nine

The last two posts built a bridge from live state into save bytes, first for objects and then for characters. This post built the bridge the other way, and then ran both of them together against a real, played save for the first time.

The load bridge decides nothing twice

Reading 69 real block files directly, in area order, was the cheap part: nothing reorders any record between reading them and splitting them back out, so the round trip is byte for byte exact from the start. Characters needed nothing new at all: the real OBJLIST already has a reader. The live state side settled more cleanly, though: rather than deciding an object's or a character's fields a second time, loading runs the real save's own data through the ordinary export, into a temporary directory, and reads that back with the engine's already tested loaders. One piece of code decides what a field means, not two.

A test that had never run against real played data before

The shipped, never-played save's 65 untouched blocks were merged with the previous post's four real, played ones, the same way DOSBox's own overlay combines them. The result is a whole, genuinely played save. It was loaded, written straight back out with no play in between, and compared against the same data.

Every block, the right count, zero exceptions

55 of the 69 blocks came back byte for byte identical. The remaining 14 are not a fault: their content is correct, only their order comes from this project's own object chain rather than the game's own unmeasured, historical write order, exactly the choice already made two posts ago. The number that matters most was never a byte comparison at all: every one of the 69 blocks kept its exact record count, with no exceptions. OBJLIST matched byte for byte except the one already recorded gap.

What this still is not

This is read, then write straight back, not a replayed session: no turn ran in either engine. The real two-way parity test would need scripted input for both and belongs to its own, larger parity framework.
