The Gate Always Goes Where the Moon Is

Moongates work in the engine now, and along the way a question that had sat unanswered for years got settled: STARPOS.DAT has nothing to do with the game at all. It is the intro film's own starfield.

Eight places, not eight gates

A moongate's entire location record is one table in the save, MoonstonePos[8][3], eight positions matching the eight moon phases. The gate itself is not a permanent structure: it appears and disappears when the hour turns, depending on whether either moon is high enough, and all eight appear and disappear together. Where a gate you step into leads does not depend on which of the eight you used: it is always the phase of whichever moon is currently nearest its zenith. Eight identical doors, one shared destination at any given moment.

The unsigned byte is the rule, not an accident

A moon's sky position is computed with int arithmetic that can go negative, but stored in an unsigned byte. That is not an overflow to guard against: it is part of the rule, and the original's own code leans on it directly. Measured the difference: of a month's 672 hours, 571 have an open gate with the unsigned byte, 582 would with a signed one. Eleven hours a month would go wrong if that one detail were smoothed over.

The gate is a real object, not a special case

Rather than build a dedicated state machine for a moongate, it is an ordinary map object: created when it should be visible, destroyed when it should not. The engine's existing drawing already understands double width objects, so the gate renders two tiles wide for free, exactly like a door or a ship's hull. The west half does nothing, because there is no object there at all, exactly as in the original.

STARPOS.DAT belongs to the intro

Its only reader anywhere in the decompilation is the intro film's night scene, never the game's own side. The moons' positions are computed from a table and the clock, not read from a file. This project's own plan had it wrong in two places, both now fixed. The file never needs building into the game as it stands today.

What stayed unbuilt

Burying and digging up a moonstone would need a generic command that targets a tile, which does not exist. The Gate Travel spell would need a spell system, which does not exist. Refusing solo mode, breaking off combat and clearing a red gate underfoot would each need a system that does not exist. Four reasons, one shape: no missing rules, missing systems underneath them.
