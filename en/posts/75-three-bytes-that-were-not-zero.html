Three bytes that were not zero

M14's slice F5: what a creature is carrying. The previous slice built the creature generator and left its last line unwritten, exactly where the original hands a new creature its spells, weapons, armour and treasure. This slice writes that line. But before it could, two tables had to be found that nothing in this project had ever read, and finding them turned up ten disagreements with the transcription and two bytes that were not zero where they were supposed to be.

One byte run, two measures

Described plainly, the tables are simple: a 64 entry index table gives an offset into a byte blob, and the blob carries four zero terminated lists per class, spells, weapons, armour, treasure. But the decompilation's own stated address for the index table is not where it sits in the owner's own GAME.EXE, so both tables had to be found by searching. The blob turned up by the one byte run its own content makes, a single hit in the whole file. Its base was confirmed by a second, independent measure: thirty four distinct non zero offsets build thirty three consecutive pairs, thirty two of which fit exactly at the chosen base, and every neighbouring base fits between one and eleven. The index table turned up by its own discriminator, the best positional match scoring fifty four of sixty four, with the next best real candidate stuck at thirty.

Ten disagreements, none of them averaged away

Ten of the index table's sixty four entries disagree with the transcription. Five of them (the acid slug and four other zero classes) sit exactly where the chosen index table position physically overlaps the last three bytes of a neighbouring, already measured trait table. The other five (a skiff, a raft, a balloon, a cat, a set of stocks) sit exactly where that same index table runs eight bytes past the blob's own start: entry sixty's own address is literally the blob's own independently measured base, and entry sixty two's raw value is larger than the whole blob, which rules it out as a real offset outright. Both groups ended up following the transcription's zero, not because it is tidier, but because every one of the ten classes is plausibly empty anyway and the raw numbers are not plausible table values at all.

Two bytes that were not zero

This part was not expected. The transcription and the measured 318 byte region match on 309 of 318 bytes, and the nine differences sit at exactly two edges, not scattered across the table. The peasant's own spell list terminator reads 0xB0 instead of zero, so a mechanical reading gives this class three spells instead of the transcription's empty list, one of them outside the valid range for a spell number altogether. The tangle vine pod's own spell list runs three bytes past its transcribed terminator before finding one, and continuing further would run straight into readable program text, "time divides!" and "critical!". That was also the independent proof of the blob's real length: 314 bytes, not the decompilation's own, flagged as uncertain, 318. Neither anomaly was patched toward the transcription by guessing. The table is bounded at the measured length, which stops the runaway into text, and otherwise reads the bytes as they are; both are pinned by a test rather than hidden.

One correction to the brief, read from the handler

The brief claimed ammunition stays unowned, the same as a spell. The handler's own line gives an arrow or a bolt the owned bit directly. The rule is now "everything but the spell is owned", read from egg.c itself rather than from a summary, which was wrong on exactly this one point out of ten.

A chest that does not fit directly

The original gives the chest a hold whose owner is the creature's own actor number, which works in the original's single, unified object and actor number space, where an actor is itself an object. This engine keeps actors and objects in two separate tables, and that hold specifically requires a real object id. The chest gets the same "carried, not worn" choice the engine already makes elsewhere for an actor owned item; the chest's own contents, once the chest is a real object, use exactly the hold the original means there too. Both halves are named, not folded into one silent simplification.

A test that found its own fault in the generator

The first discriminator tests seeded a fresh generator for every single trial with small, sequential numbers and read exactly that first draw. Seven tests failed systematically, not randomly, and the cause was not in the production code at all: the generator's own, documented remark says outright that the first handful of draws after seeding a small number is visibly poor quality, a warning about a wart rather than a bug, warts included. The fix was one continuously advancing generator per test, not a reseed every round, which also matches how the game actually uses its own shared generator far better.
