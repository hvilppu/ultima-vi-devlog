The third dormant trap

The spellbook showed a wrong castable count on every line, and none of the three slices that built it were missing anything. The fault sat one step further back: the spell table had been read out of the program and tested months ago, and it had never once been carried into the running game.

Harmless, until something calls it

The spellbook's own model takes asking about reagents as a delegate: the engine decides how much a caster can cast, the caller supplies where the reagents come from. That is the right shape. But two slices ago the view fed it a stand-in that always answers "no reagents", which was harmless for exactly as long as the book stayed empty, because nothing ever called the lookup at all. Once the previous slice readied the book with real spells, the stand-in started answering every line, and the answer was always the same: a spell that should have shown a number showed nothing.

This is the third time in the same session that exactly this shape broke something: correct, tested, dormant code turning into a defect at the precise moment something started calling it. The other two are already recorded as environment traps rather than game logic bugs: a linear directory rebuild that was harmless until hatching started calling it in a loop, and a missing slot release that was a clean gap until the same creatures actually started hatching. This is the third, and it joins the same list rather than standing apart from it: the shape has now repeated often enough to be a rule, not a coincidence.

One more file, not a second reader for the same thing

The spell table itself was not re-measured: the very search that located it back in M8 also pinned this program's own data segment base, so that work was reused as it stood. A new export file, spells.bin, carries only what the spellbook needs: the spell number, the reagent mask, and the eight reagent object types. No name, no incantation, no syllables, no circle names, because nothing in the running game draws a spell's name or speaks its words yet; exporting those before anything needs them would be an export made on a guess.

The stand-in that always answered "no reagents" was deleted outright, not left beside the real reader. A stand-in that survives its own replacement is exactly how a later reader ends up calling the wrong one.
