Seven Invented Lines, Six Already There

The spell layer turned twenty outcomes into seven English lines that I had written myself. Six of those seven are a row of the message table this project had already exported, checksummed and pinned by index. So the game was printing a paraphrase of a line it was holding the real text of.

The rule that decided what converts

A build session had refused to give these an identity before this, and its reason was a good one: an enum value is not an identity. One value can stand for several engine branches that print different things, or nothing at all. That is true of one of the twenty, and treating the whole group as impossible left the most used path in the game speaking my own English.

So the rule was written more narrowly: an outcome converts to read the original's own row when exactly one engine branch produces it and that branch declares one index. Anything else is named and left alone. Reading all twenty three values through gave exactly three groups: nine convert, five stay named as a collapse, and nine declare no row at all.

Silence where the original is silent

Two of the row-less ones turned out, mid build, not to be unbuilt rules but measured, built branches for which the original prints nothing. Six halo duration spells and four winds go through the original's other spell switch, and that switch has no message tail at all: it never sets a result variable anywhere inside itself, and its cases do the halo, the effect and the slot write without printing a word. This project printed its own success line for both, because the old rule assumed every successful cast says something.

The question was left open in the slice that found it and measured a second time independently before the change was ordered, because it changes what a player sees. Now neither produces a row, not even a blank one through the same path: a blank row on a scrolling text area would wipe what the player was reading, which is not silence but a second event.

Two default arms, and the answer one call away

Two outcomes stayed named as a collapse for the same reason: each came from a three armed switch whose default arm folded three different results into one. Success, done with no message, and done with the message already printed. Those three do not print the same thing, so one row would be wrong for two of them.

The measurement found the answer one call away from the code that threw the question out: a neighbouring routine already resolves all five result values into their own row and sound, measured and tested in an earlier slice, and the outcome never read it. The outcome lost the result, so the status line had nothing left to ask.

The brief was wrong twice, and the building session right twice

This is the most interesting part of the post, and it is not what got built.

First the count. The brief claimed exactly one outcome folded three results. Reading every value found a second one, on exactly the same pattern, in another spell family. Two fold, not one. The correction was recorded as such rather than the number being quietly changed to match the finding.

Then the shape. The next brief, mine, argued that for a status line the two done results are the same answer, no row, so two outcomes per family would do. The building session disagreed and was right: that holds for the row and not for the reason. One of them is the original printing nothing; the other is an effect that has already printed something, and the branches behind it disagree about what. Folding them forces one reason onto both, and either reason would be false for half the results that reach it. That is the exact shape the previous slice's own tests forbid. So three per family, and the argument for it is better than mine.

The same session found, in passing, one sentence that was wrong beside correct code, and declined to fix a file it had been told not to touch. That was the right call, and the fix came as a measurement: the summary of the done-with-no-message result said a failure sound is played for it. The switch's epilogue excludes that value from the test that plays anything and then fails the success test beside it, so nothing is printed and nothing is played. That sound belongs to the arm that catches a value outside the five named ones. The code was right and the sentence was attached to the wrong value.

And one number I got wrong myself today

The document's first draft said the default arm was split into five. It was split into three: the default arm folded three results, so undoing it gives three outcomes. Five is the number of result values, which each family now resolves completely, and that is a different fact about a different thing. The wrong number was in eight places across three files and is corrected in all of them. The two true numbers sit one sentence apart, which is exactly why this is written here rather than quietly fixed.

What a player sees

Not one new spell: all eighty reached their handler before this. The change is in what the message area says. Eleven outcomes of twenty eight now read the original's own words, where seven invented phrases used to cover all twenty three. Four say nothing where the original says nothing. The remaining thirteen keep my own English, named as their own group for three distinct reasons (branches collapse, the rule is not built, or the row has not been measured) rather than quietly mixed in with the converted ones. The invented success line survives on three outcomes only, and they are exactly the three whose row has not been measured.
