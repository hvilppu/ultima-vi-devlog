An egg that hatches only once

M14's slice F6: the eggs hatch. The previous five slices built the object store, the player's own Attack command, actor creation, the creature generator and what it carries. This slice is the one that calls all of them: an egg sitting invisible on the map, deciding whether it should open, and doing it exactly once. The F9 development key, which has been the only way to get a hostile creature into the game at all until now, has its own documentation saying outright that this is the work it stood in for.

The percentage is a one shot, not a chance taken on every visit

An egg's own quantity is the percentage chance to hatch, and the obvious wrong reading is that the game would roll it again every time the player walks past. The original does not. EGG_hatches rolls once, and whatever happens, the egg is marked hatched and invisible afterward: a failed roll spends the egg exactly as a successful one does. A rare encounter stays rare for exactly this reason. The test proves it directly: a one percent egg, a roll that fails, and the next call on the same egg never rolls again, it only checks the hatched bit.

Two faults, neither one fixed

egg.c keeps its own combat mode variable alive for the whole call to one egg, outside the embryo loop, and only ever raises it out of motionless once. The first embryo that supplies some other mode gives it to every later embryo's own creatures in the same egg, regardless of what mode their own quality would carry. A mixed egg of two creature types therefore behaves wrong in one consistent way, not right in two different ones.

The second is quieter. The gargoyle grazing test asks every party member in turn whether they are a gargoyle, which is correct, but its amulet half always asks object one, the Avatar, a literal one in the code. Give the amulet of submission to a companion and leave the Avatar without it, and the egg's gargoyles still fight, because the test never once looked at the companion's own inventory. Both are recorded in originalBugs.md and reproduced faithfully, not fixed.

The whole level, not a forty by forty window

The original only hatches eggs inside its loaded 40 by 40 window, because that is all it ever keeps resident at once. This project keeps the whole world resident all the time, the same departure already named at the object store's own limit, so the area sweep searches the whole level directly. It never changes which egg hatches, because the window never touches the distance, local or forced rule itself; it can only hatch an egg sooner, never differently. The performance side is still named: HatchEggsNear only sweeps again once the same aligned area, using the original's own (coordinate - 16) & ~7 formula, actually changes, not on every single step.

A deleted creature does not vanish empty handed

A creature whose placement fails is deleted, and the first draft left its own possessions hanging on the freed slot as a named gap. That was the wrong reason to leave the rule out: the rule is already measured and already built. U6ObjectWorld.Destroy spills a deleted object's own contents onto its square rather than destroying them with it, and the original's own call order, possessions from the generator first, the teleport only after, makes that same rule reachable for an actor too. DeleteGeneratedActor now spills whatever the creature directly carries onto its own square before the slot is cleared, and a new test proves it: a creature whose placement fails leaves its items on the ground, and no item still names a slot that has been freed.

What this does not do yet

The silver serpent's segment chain and the tangle vine pod's four vines are measured but not built: both are their own, separate geometries whose description is waiting in docs/u6-munat.md for the next slice rather than a re-read of the source. The armageddon gate is named as a parameter, because this project carries no such flag. The companion's own "hears something" warning gets its direction and its roll, but not a printed line, because nothing in this project yet turns a direction into text or knows whether a companion is alive, in the party and close enough.
