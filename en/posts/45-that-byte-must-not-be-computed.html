That Byte Must Not Be Computed

M18, save and load, is underway. Its whole point is stricter than any earlier round: not "behaves correctly" but "produces exactly the same bytes as the original." The first proof already exists, and finding it turned up the same surprise twice.

One byte no game state explains

When the original writes a contained object to disk, it writes exactly two bytes of its real container reference and leaves the third untouched. That byte is stack memory that was never anything. In the owner's own data, 1208 of 1638 records would imply an impossible level if read as a position. There is no formula for it, because it describes nothing: the only correct implementation is to carry it through completely unchanged.

The same surprise somewhere else, found by building rather than measuring

A character's fourteen byte name field ends with a NUL, exactly as it should. But what follows is not zeros either: the Avatar's own name is "Avatar\0ion\0\0\0\0". Some longer name or word left its mark in the buffer, and the original never cleaned it up. This was not the measurement's own finding but the writer's: a byte for byte rewrite test failed at exactly this spot, because building the name from a trimmed string writes zeros where the original has "ion". The fix is the same as for the contained object's byte: carry the raw fourteen bytes through, do not rebuild them.

Two proofs, not yet four

Built and proved byte for byte against the owner's own copy: all 69 OBJBLK?? files read and write back identical, and the whole OBJLIST the same way. Two bigger pieces remain: knowing which of the 69 files an object belongs to once the world is live rather than one file being read at a time, and one real save from the actual game, which does not exist yet. The owner's own copy has never saved a game.

An old warning turned out to be wrong

An earlier round recorded a warning: there is no pristine source for the numbered characters, so running the original in DOSBox should be done with a backed up SAVEGAME/. That was wrong for lack of measurement. The game's own uncompressed starting state files carry the whole OBJLIST as their own tail, byte for byte. The entire shipped save directory is reconstructible from those two files. A backup is still worth taking, since it is cheap, but it is no longer the only protection.
