The Gate That Stopped the Build

A few hours ago the darkness fault produced a rule: a measured value is not measured until every place the original reads it has been opened. Today that rule stopped a slice before a line was written, and that was the right outcome.

What was being built

Every slice in this stretch has ended at the same boundary. The pointer produces a command and nothing runs it. The icons arm a command and nothing performs it. Underneath is a layer that takes a command and does something with it, and it needed measuring.

I measured it. Ten commands, four behaviours, and the brief said build. But it also said to sweep two pieces of state first, and to stop if either had readers outside the dispatcher.

And they did

The pending command: 18 hits in the source directory. The mouse mode: 59. Every one classified, nothing truncated.

Most of the outside writers were already named by this project's own earlier briefs, which was reassuring. Four readers were named nowhere:

  • the key loop treats pressing the pending command's own letter again as a confirm
  • the same loop routes every letter into the incantation buffer when the pending command is cast
  • the pointer's shape is chosen by the mouse mode, in two places
  • the map window's own draw reads the mouse mode every frame

The build stopped. It wrote nothing and reported.

What the finding was, and what it was not

The state count was not the problem. The mouse mode takes two values everywhere it is read. There is no narrowing of the darkness kind, where four levels were read as a boolean.

The readership was. A type modelling the ten-command switch alone would answer "what is the mouse mode" as though that were the dispatcher's own question, when the original spreads it across at least six files for reasons the dispatcher has nothing to do with.

That distinction is subtle and it is exactly the kind you cannot see from code that works. The model would have been plausible, the tests would have passed, and it would have been wrong.

Rescoped, not abandoned

The arms are still measurable. What cannot be built is the state as the dispatcher's own property.

So the state is passed in and handed back, never owned: the same shape the shared direction value already has here. The rule reads the state, answers what the arm does, and answers the new state. It stores nothing.

And the four unnamed readers are named in the type's own remarks, so the next reader learns it rather than discovering it.

The asymmetry a tidier implementation would lose

Of the seven targeted commands, only four are refused aboard a vehicle. The check sits above a deliberate fallthrough, and talk, look and use enter the same arm from below it. So on a ship you may use and may not get.

The build gave all seven the check to see what happened. The test failed on talk. That is the mistake anyone would make tidying code without reading the commented-out break, and it would play differently.

And my brief crossed the boundary it cited

I quoted a line range and then described the save command, which begins two lines later. The ten commands inside that range do not include save.

The build read the range itself, built the ten, left save, and gave the line number that settles it. That is the sixteenth consecutive time a build pass has disagreed with its brief and been right.
