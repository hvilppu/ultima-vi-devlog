The only milestone with nothing

One milestone had no status line and no code at all: character creation. It is also the only normal entry point into the game. Debug spawn has been the only way to reach a playable state for the whole life of this project so far.

The gypsy's seven questions

SRC_U/chargen.c and transfer.c's PortraitScreen had never been read at all until now: name and sex, twelve portraits, and the gypsy's knockout tournament for eight virtues. Three rounds, seven questions, every winner adding its own strength, dexterity or intelligence gain, not just the final question. Part of the measurement already existed elsewhere: docs/u6-karma.md had already measured the tournament's own karma structure, and docs/u6-pelitilalohko.md the whole write table. Neither was remeasured, only what was missing: the question and answer tables, the gain tables, and the whole orchestration of CreateCharacter.

What was left to the visual side on purpose

The gypsy table's own vial-pouring animation, the woods scrolling by, the full cinematic reel before and after this scene: pure spectacle, none of it affects any game state. The questions' own text was never exported into this project from anywhere, so the question screens show the two competing virtues by name instead of the original's own wording. Writing guessed text would have been game data landing in the repository, and that stays forbidden no matter how tempting it is when the screen otherwise looks bare.

One line that never resets

The original's starting karma is a module level variable, set once at compile time. It never resets at the start of CreateCharacter, because the program never ran it twice without a process restart in between. This engine may let a player back out and try again without restarting the process, and the original has no measured answer for what should happen then. Resetting to 75 at the start of every attempt is a defensible choice, recorded as one rather than as a measurement.

Two sessions, one session limit in between

The build agent hit its own usage limit mid-edit, while writing the F14 key handler. The engine side, U6CharacterCreationTournament and U6CharacterCreationFlow, was already finished and tested when the limit hit, so it was verified and committed on its own before a second agent picked up exactly the missing Unity wiring. Eight of U6CharacterData's eleven write targets already existed; two were missing, AvatarPortrait and an absolute level setter, both additions following an already existing pattern.
