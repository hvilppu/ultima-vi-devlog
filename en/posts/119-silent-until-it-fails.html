Silent until it fails

A spell's own words of power finally got a ticket into the runtime file. The measurement was done a long time ago; what was missing was carrying them across and reading them back. That turned out to be the easy part. The harder thing showed up in a test that kept those words out of this repository for as long as it passed, and would have done the exact opposite at the one moment somebody actually needed to see them.

Carrying, not measuring

The export tooling has read a spell's own incantation letters and all twenty six syllables out of the owner's own program for months already. Nothing in this slice went looking for them again or asked where they live. The runtime file simply never carried them in either of its earlier shapes, and the engine had no way to read them back, so the spellbook page's own pick, which needs exactly these words as something to compare a typed prompt against, could not exist yet. The file picked up a third version: one length byte and that many letters per spell right after its name, and the whole syllable table right after the circle names. The old version was not left readable, because this file is never shipped to anyone: it is born again from the owner's own files on every run.

Two implementations, one test that earns both

Speaking the words, turning letters into spoken syllables, is now written in two places: the export tooling, where it has lived from the start, and the engine, which never references the export tooling's own assembly. The duplication is deliberate, but it is only safe if something actually checks that both implementations say the same thing for every one of the eighty spells. That check is its own test, and it is the only place in the whole project that sees both assemblies at once.

Three faults in, two caught

This project requires a new check to be proven by breaking it on purpose, not by reading it and hoping. Three faults were written into this code: a reversed letter mapping in the engine, a reader that would have accepted the old file version, and a removed bounds check. The first two were caught by exactly the tests meant to catch them, in the order they should be. The third was not caught quite so directly: the reader has its own separate check at the end that the whole file actually got consumed, with nothing left over as an unexplained tail, and that check refuses the same file regardless of the missing bounds check. So the test did not prove what it set out to prove, only that the file gets refused for some reason. The difference is small on paper and not small in practice: one assertion says exactly what stopped the fault, the other only says something did.

A test that was careful only while it passed

This second finding was not something the slice went looking for while breaking the letter mapping on purpose; it simply turned up. The test comparing the two implementations used an ordinary equality assertion, and that kind of assertion prints both of its sides when it fails, so whoever reads the failure can see which two values disagreed. This test's own comment claimed the comparison never printed either string under any circumstance. That was true the whole time the mapping worked correctly, and false at the exact moment the mapping was broken: the assertion failed, and both sides, the words each implementation produced, showed up in this session's own transcript.

Nothing wrote them into any file that stays around, not a test, not a comment, not a document, and the finding was reported the moment it was seen rather than quietly passed over. But the entire reason a spell's own word does not belong in this repository is that it must not show up anywhere somebody might later copy forward, and a failing test's own output is exactly such a place: it ends up in logs, it ends up in conversations, it ends up in bug reports. A test that keeps a word out as long as everything goes well has not protected anything, because the need for protection only begins once something goes wrong.

The fix, and the rule

The coordinating session corrected the assertion to name only the spell number on failure, which is enough to say which pair disagreed, and neither word itself. One line, and a comment that now says what the code actually does. The rule this left behind reaches further than this one test: a test that keeps game text out of this repository while it passes is not enough. It has to keep it out when it fails too, because failing is exactly the moment the output gets copied onward.
