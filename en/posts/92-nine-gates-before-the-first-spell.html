Nine gates before the first spell

The spellbook opened, the pages turned, and a line could be selected, but the selection never had any consequence. Seven earlier slices measured the casting rules and three built the book, and every one of them stayed out of the player's reach, because nothing ever fired the selection. This slice is the capstone: pressing the key now actually casts.

Nine steps, not one big decision

The original checks nine things in order before a spell even gets a chance to happen: negate magic, an empty book, nothing selected, the caster's level, their magic points, and the castable count, in that order. The last three were already measured and built as their own class (U6SpellCast.TryCast) long before this slice: the work here was connecting the first three gates and the spell's own selection to that, not rebuilding what already existed.

The cost a player notices

Every refusal was tested on its own, to prove that no reagent, no magic point and no movement point is ever spent when it fires. Nine gates, six of them a refusal, and missing even one test would have meant a player losing a reagent to a spell that never actually happened. That is exactly the kind of fault that does not show up by reading the code, only by playing against it.

A bit that never needed masking

The original reads the castable count out of a stored byte whose top bit carries the selection marker: the gate reads it masked, & 0x7f, and a port that forgot the mask would see the selected spell's count as at least one hundred and twenty eight, and would never refuse it for want of reagents. This project never packed the selection bit into any number in the first place, so there was nothing here to mask. The test pinned the claim directly anyway, because the claim is the thing that has to be proven, not what the code happens to look like.

A name collision between two fields

Small, but the kind of thing that would have quietly broken everything: this project's own character model has a field named "level" that means the map level, the dungeon depth, not the caster's own experience level. The original's own table the casting gate reads is the latter. The shared English name is a translation coincidence, not anything in the original's own structure, but reading the wrong field would have gated every cast on which dungeon floor the caster happens to be standing on. Confirmed from the export's own write order before a single line reached the gate.

The same kind of input as the Attack command

The view needed one new key to cast and one way to choose a target for the spells that need one. The second one is exactly the same answer as the Attack command already gave: arrows move the aim, space confirms. No new input shape, just the same one reused somewhere else.

What this does not cover yet

The spell's own effect. Seven of the eight shared handlers already cover 61 of the 80 spells and are built, but nothing yet connects a spell number to any of them. This slice stops exactly at the point an effect would run, because that connector is its own, named piece of work, not this one's. The words of power do not print in the view either: the name has made it into the running game, but the words have not, so showing them stayed a named gap.
