What the winds ask of a class

The previous two slices built the wind's own path and a door into dealing damage without a blow. What was left was three spell effects that should not have needed any new measurement at all: flame, poison and death each need a fact about the target's own class, and the lookup for exactly that already existed for a different purpose. The job was not to go looking for anything new, but to extend one existing lookup by three bits.

One lookup, not a second one beside it

U6TestSpawn.ReadCombatTraits used to return two flags, undead and immune to death spells, to classify the skeleton and the giant rat. The three new flags, immune to fire, double fire damage and immune to poison, already existed in the exported class table's own bit set; they just had not been read for this. Extending the same method to five flags kept the path simple: two separate readers over the same table would have been exactly the kind of stand-in this project has already recorded as a defect once.

An open question, closed by reading the original more closely

The previous slice left open whether the amount the death wind deals (the victim's own hit points) matches the original's own kill routine. The original's source gives the answer directly: SPELL_KillTarget calls the damage routine with exactly the victim's own hit points. The implementation was already right before this slice; the question is now closed rather than merely unmeasured.

An unknown class is immune to neither, for two different reasons

Fire guards explicitly: an unknown class skips the immunity test in the original, written that way on purpose. Poison does not guard at all, a different routine written slightly differently in the same file. This project's own lookup already answers "no" for every flag on a class it cannot find, so the two different original reasons land on the same answer here, and neither needed its own separate guard.

The lazy roll: no random number when the answer is already known

Three routines read immunity before rolling at all, and the roll sits inside the very branch the immunity test guards: a known, immune class consumes no random number at all for fire or for death. Poison's own contest is the same. The energy wind alone rolls its own unconditionally, because it has no immunity branch to sit inside. This was proved by seed comparison: the same class, the same starting state, and after flame the generator is exactly where a fresh one would be, while after poison it is one draw further along.
