Ultima VI rebuilt

Notes from a 1:1 reimplementation in C# and Unity.

199 out of 199

One instruction was missing, and with it every character in the game can now be approached, talked to and left without anything throwing along the way.

The instruction prints a string. Not text the script spells out, but a string it names from somewhere else. Until now it was the only reason one conversation out of 199 would not start at all.

Measured first, and the measurement was wrong

I began by counting how often the instruction is used. The answer was 25, in two shapes: 24 name a string out of an array inside the script, and one starts with the byte 0x53, which is the letter S.

That one was not an instruction at all. It was character 181's own number in the script header, and 181 in hex is 0xB5, the same as the printing instruction. My walk started at the beginning of the script and did not step over the header, so it read a character number as an instruction.

The real count is 24, and all 24 are the same shape. The original has three shapes and two of them never appear in the data. I implemented all three but recorded that two of them were read from the decompilation rather than measured from data. That distinction matters: measured is certain, read is my best understanding.

The shape nobody uses is odd anyway

The text variable shape is not an expression but a hand parsed sequence: 

B5  <byte read and ignored>  <index>  B3  <byte stepped over>

Two bytes that are never looked at, one at each end. A real script would probably put the start and the end of an expression there, but since no script uses this shape I do not know that, and I am not claiming to.

My test passed without distinguishing anything

I wrote a test for that shape and it passed. Then I did what I have learned to do: I removed the skipping of that last byte on purpose, to see whether the test would fail.

It did not.

The fault was in my test script. I had put the end of an expression in that last byte, which is what I assumed a real script would do. The end of an expression does nothing when it is executed either, so the test could not tell the difference between the byte being skipped and the byte being run. It was confirming safety that was not there.

I changed the byte to a letter. Skipped it stays silent, executed it is printed. Now the same mutation fails the test. A second mutation in the same run, walking the string array as a word array, failed its test immediately, so that side had been right from the start.

This is the second time a mutation run has caught a test of mine. Both times the test read perfectly sensibly, and both times the only way to notice was to break the code.

The numbers moved, and in the right direction

Three corpus tests failed, all on pinned numbers, and not one hand written test moved. That is exactly the right signal: the change hit what it was supposed to hit. 

                              before    after
openings waiting for input       172      173
openings unimplemented             1        0
keyword lists matched           3057     3065
answers unimplemented             89       36
conversations begun and ended    198      199

89 minus 36 is 53, and 53 is exactly the number of answers that reached this instruction. I measured the numbers by running and pinned them afterwards.

What this means

Every character in the game can now be approached, talked to and left. Name, portrait, description, opening statements, questions, keyword matching, answers and departure. 199 out of 199, and none of them reaches an unimplemented instruction on the way. 

U6Engine.Tests   423 / 423   without Unity
U6Formats.Tests  266 / 266
U6Export.Tests    38 / 38

Two things still throw, and neither stops a conversation from starting: writing into an array inside the script, and searching a string.

The first of those is the last piece that needs a decision rather than just an implementation. To the original a loaded script is editable working memory; to me it is still only bytes to read. That difference has to be settled before a shop and a user interface are built on top of it, not afterwards.
