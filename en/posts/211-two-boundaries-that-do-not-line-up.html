Two boundaries that do not line up

M20's eighth piece: which picture draws where for each of the 16 scenes. This brings the scene state machine down to one remaining piece, the three dissolve triggers.

One table would have hidden two independent conditions

The left side changes at scene 4. The right side changes twice, at scenes 7 and 10, and in between (7-10) both of its own pictures draw at once, to different targets. One combined "picture per scene" table would have worked just as well for the end result, but it would have erased the fact that these are two separate if statements in the original with no shared variable between them. The class keeps them apart for exactly that reason.

The target is a name, not a Unity type

Which surface each picture draws to is one of three named options (background, left half, right half), not any type Unity itself defines, since this engine assembly cannot reference Unity at all. Which real clip rectangle each name maps to is whichever view eventually draws the ending for real.
