Eighty-five of eighty-five

The last post left the ending behind F13 and named its "own trigger chain" as next. That chain was already measured, a good while ago, in a different milestone entirely. This post is about finding the measurement rather than making it again.

The last of eighty-five usable types

M13, the object-specific use logic, was marked done except for the types waiting on other milestones. The vortex cube was the last name on that list: using it requires the ending, and the ending did not exist. Then it did, behind a development key, and the last name on the list turned into a question rather than a block.

The measurement already existed

docs/u6-paatehtava.md's own sixth section had already measured the vortex cube's full launch condition back during M17: all eight moonstone frames in the cube, each lens on its own exact square, the Codex on its own square (true from the start of the game), and the party leader inside an eleven square window around the Codex. Two independent sources confirmed the same numbers in different shapes, the byte trace and the drawing code's own light-ray test, which is exactly the standard this project asks of a number before it is allowed to become code. This round's own work was reading that measurement, not remeasuring it.

What turned up along the way

One detail was easy to miss: all three location lookups (each lens, the Codex) search level zero, literally, never the player's own current level. The dungeon level is excluded entirely through the window test, not through a condition of its own: a dungeon's own coordinates are 0 to 255 and the window sits at 918 to 928, so standing in a dungeon can never land inside it. This was already on record in the measurement, and it was the exact spot a wrong reading would have produced the right kind of wrong answer: "does not work in a dungeon" and "does not work because the level does not match" sound alike and are not the same claim.

Four tests that changed

Three existing tests named the vortex cube specifically as an example of a type with no handler: one directly, two as a side effect of their own boundary tests. All three were right when written and wrong now, which is exactly the rot this project has already recorded three times over on the same list: the vehicle types, the potion, the gem. A fourth will be some other type, some other day, and that is the whole point of keeping the list.
