The Shrine Speaks by Quality

M17's first piece, the main quest, is fully measured now. The biggest finding shrank it: it is objects and conversation script flags, not an engine state machine. Most of its mechanics need the same missing piece, a generic use command aimed at an object, and stay open for that reason. Two small pieces do not need it, and they are in the engine now.

A past conclusion was wrong

The moongate round left burying a moonstone unbuilt on the grounds that it "would need a generic use command that targets a tile." That reason was wrong. In the original, a use command always points at an object, never at terrain: burying a moonstone targets the moonstone itself and reads the terrain under the active character as a side effect. The real reason is a different missing piece, a generic use command aimed at an object, but that same reason now covers three things instead of one: using a rune, burying a moonstone, and using the vortex cube.

One primitive, not three

All three ask the same question, "what object is here," three different ways: a rune checks eight neighbouring squares, the vortex cube checks three fixed coordinates, a moonstone does not ask at all and just reads the terrain. In the original, all three call the same four line function. There are genuinely four separate capabilities, and this engine already has two of them: a type lookup on a square and a container's own contents. A rectangle query and a terrain tile read are still missing.

The shrine speaks by quality, not by number

The original's talk dispatch has one special case: a shrine and three statues carry no script of their own, and their quality is the script number to run instead. This was entirely missing from the engine, because nothing ever searched nearby for anything but a numbered character. One new search function fixes it: it finds the nearest shrine or statue and answers with its quality, and starting a conversation never knew or needed to know the difference to begin with.

A shrine's own square is a wall regardless of the force field

This settled a question that was not even obvious to ask beforehand: does raising a virtue need the force field cleared first? No. A shrine's own tile is impassable and a wall in every direction, force field or not, so approaching and talking to it never depended on using the rune at all. Raising a virtue is entirely inside the shrine's own script, whose ADDKARMA and ADDLVL were already built in the previous round. One search function was all it took to open the whole mechanism.

A variable that neither forgets nor remembers wrongly

The Sacred Quest flag behaves differently from karma and the Gargish flag: it is never seeded at a conversation's start and never written back at its end. It is a live variable for the whole game, and in this engine that means leaving it alone entirely: once the conversation variables are one instance for the game's whole lifetime, doing nothing is the correct answer.

What stayed unbuilt

Clearing a rune's force field, burying and digging up a moonstone, and the vortex cube's actual ending trigger all stay open, because none of them need a new rule, only that same missing use command. The trigger's exact point is measured anyway: one far call, occurring exactly once in the whole file, that hands the process off to the ending. Once the use command exists one day, the trigger is one check and one call away.
