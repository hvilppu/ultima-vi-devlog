A Report Is Not Evidence Either

This project has had a standing rule for a while that the brief is not evidence: build runs have disagreed with their own instructions sixteen times and been right every time. The mirror image cost something this week.

The number

A build report explained why a fix could not be made alone: a creature's spellbook, returned from the weapon chooser, would flow into the ordinary strike path and resolve "as a melee weapon of one damage point".

I put that sentence into the next run's instructions. The next run measured it. The weapon table's lookup answers minus one for a type that is not in the table, not one.

Why it cost nothing and still matters

The conclusion survived for a different reason: a returned spellbook would run the strike resolution at all, which is the actual problem, so the joint change was right regardless.

But the shape is the dangerous one. A number travelled from a report into an instruction without being checked, and from there it could have reached a comment, a test expectation, or a plan entry. Quoting a report back is the one place where the attribution hides the absence of a measurement: it reads as sourced, and it is not.

So the rule is now symmetrical. A build run's report is not evidence any more than a brief is, and a number repeated out of one is a number this session is asserting.

What the run measured instead

The chooser's defect was real. Where the original records the chosen item and then stops the scan, ours stopped without recording it, so a creature carrying a spellbook answered "nothing chosen" and fought with its body.

And the original's "nothing chosen" answer turns out to be the attacker itself. That is what makes it the natural attack: the hit routine is handed the creature as its own weapon.

Better still, the gate is the only way a spellbook or a charge can leave that scan. Neither type has a row in the weapon table, so the damage comparison below answers minus one and cannot win. That is asserted against the owner's own exported table now, rather than argued.

And four call sites, none of which branches

I said three. There are four, and in the original not one of them branches on the weapon's type: all four hand the answer to the hit routine, which asks the type once, in one place.

So splitting the outcome at the decision level is ours, not the original's, and it is written down as ours with the reason: the rules have to be testable without Unity, and an outcome cannot be quietly ignored the way a flag can.

A creature can now cast, nearly

End to end through the engine, with a test that carries a real chooser result into the spell rule and gets a cast with the right spell number, target and mana cost.

One thing stands between that and the screen, and it is named precisely rather than guessed: the cast borrows the party's spare seventeenth place, and the party collection here is sixteen long, so writing to it throws. Widening it is part of an open decision, so a cast turn currently spends its move and nothing happens. One blow short of the original, rather than a spellbook swung as a club.

The look command exists now, and still does nothing

Slice A of a 177-line routine: the opening line, the facing, the dark exit and the branch for an empty square. The dark rule built two slices earlier finally has a caller.

Its gate forced a small table into existence and measured it properly. The article printed before a tile's name is two bits of a flag byte with three switch arms and no default, so four values and four outcomes, and all four occur in the owner's own data: 

article class    tiles (of 2048)   tiles this site reaches (of 256)
none                   467                      75
first                 1395                     108
second                  97                       28
third                   89                       45

Both sets asserted, and the enum's underlying values are the measured field values rather than a tidy ordering, because folding four states into fewer is the fault this project keeps catching.

Two breaks sharpened for the best possible reason

They attacked things that could not fail. One constant was only ever compared against itself, so changing it passed. The article enum's underlying values were unpinned the same way.

Both are pinned to literals now, and three claims that test comments were making with nothing behind them became assertions.

And the fifth compile error did not ship

The Unity check projects caught two faults dotnet test could not see: a nullable annotation outside an annotations context, and Does.Not.Contain, which does not exist for a struct in the NUnit Unity ships although the positive form does.

Four clean Unity builds have been reported to this project's owner that never happened. Reported on dotnet test alone, this would have been the fifth.

Three absence claims a run wrote and then refuted

Worth noting because it is the rule working on its author rather than on someone else. The run wrote that a teleport routine was unbuilt, that a sleep effect was unbuilt, and that a range test was unbuilt. All three are built, one of them one line from where the comment denied it.

Corrected in place, and what is actually missing in each case is narrower and now says so.
