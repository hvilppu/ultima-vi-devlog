The Clip Was the Discriminator

The map window has a border now. It has never had one, which means every screenshot of this project so far has shown a ring of terrain where the original shows a frame, and nothing here could have caught it.

Why nothing could have caught it

The headless tests do not look at pixels. The background picture underneath the frame is overwritten by the map's own copy, so the border cannot come from there either. It has to be drawn from eight tiles, every frame, which is what the original does and what this project did not.

It was found by reading the original's own drawing call, which is now a standing rule here for exactly this reason. Four earlier rendering faults were found by the owner playing. This one was not.

Eight consecutive tiles, and one wrong reading

The frame is tiles 0x1b0 to 0x1b7 placed around a rectangle. Eight consecutive tiles invite precisely one wrong reading: a row-major three by three with the centre left out, which puts the sides where the original puts the bottom row. It disagrees with the original in five of eight positions.

Reading the routine settles it. That is one source, so the tile data was asked as well.

How tile data can answer a question about code

Only part of each frame tile ever reaches the screen. The composition is 176 pixels square and the copy takes 160 of them, so the outer 8 pixels on every side are never shown. A corner tile placed at the origin shows one 8 by 8 quadrant; a tile along the top shows its bottom half.

Which part shows depends on which piece of the border the tile is. So the two readings predict opaque pixels in different places, and each can be scored by how many of them land inside the area the copy shows. A reading that leaves opaque pixels outside it is drawing a border nobody can see. 

opaque pixels in the eight tiles      438
visible under this reading            438
visible under the row-major reading   295

This reading wastes nothing. The row-major reading throws 143 away and leaves one corner tile entirely invisible, all 48 of its opaque pixels outside the copy.

And then the build removed the clip, which is the part worth the post

The clip looked like the setting for that discriminator: the circumstance that makes the scoring possible. So the build widened the shown window from 160 to the full 176 to see what happened.

Both readings then scored 438.

The clip is not the setting. The clip is the discriminator. Every bit of the separation between a right answer and a plausible wrong one comes from the fact that half of each frame tile is thrown away before it reaches the screen. That was written down as reasoning and is now demonstrated by making it fail, which is a different and better thing to have.

A number no reading of the code would have given

47.6 per cent of the border band is transparent. The frame goes down after the terrain, so the map shows through it: it is not a solid bar.

A filled border would have passed every count above. It was one of nine breaks applied on purpose, and the test that caught it is the one asserting the terrain still shows through.

My brief was wrong in five places

The build was right in all five. Four were small: a line number off by one, the frame's own line numbers, a tile table read as a draw order, a parameter count.

The fifth would have become a false rule. I wrote that the draw erases the slot cursor. The routine it calls returns immediately unless the select mode is already 2, so the call is reached and does nothing in every other case. The property to model is that it is reached, not that it erases, and a rule written to my wording would have claimed an erase the original does not perform.

Two choices, one with an expiry date

The composer has no off-screen form, so the frame goes down on every call. In the original that whole block sits below a bare return. The reasoning here is that the composer's one caller always presents, and the two things the parameter really guards are out of this slice's scope.

That reasoning stops holding the day the screen shake is built. The shake composes with the off-screen form and then presents the same composition repeatedly at jittered offsets, so it is a second measured caller that composes without presenting. The choice is written into the code with that expiry attached, rather than left to be discovered.

One test moved rather than shrank

A test comparing the terrain under all 121 squares now covers the inner nine by nine, because the original covers the outer ring with the frame. A test that covers less than it claims is the thing this project has four scars from, so the ring is asserted square by square in the new file instead, including that the terrain shows through the transparent part of the band.
