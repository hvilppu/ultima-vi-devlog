A Pixel at a Time, Not a Tile

The line of fire for M14's third slice is now measured and built: COMBAT_Missile and the Missiles function it wraps walk a shot in world pixels, sixteen to a tile, starting at the source tile's centre, rather than one tile at a time the way any reimplementation would naturally write it first. The difference is not a style choice: it changes where a shot stops.

Same line, a different set of tiles

Over all 224 offsets a shot can be aimed at, 182 of them test a different set of tiles under the pixel walk than under a tile walk, and the difference is one directional: the pixel walk always tests a tile the tile walk never does, and never the other way round. A tile stepping version would therefore be systematically more permissive, not merely different: it would let shots through walls the original stops, and would never block one the original lets through.

A corner movement would refuse

28 of the 224 offsets enter a tile diagonally, both coordinates changing on the same pixel step. The code commits to that tile without looking at either orthogonal neighbour, so a shot passes between two walls that touch only at a corner. Movement refuses exactly this, through __TryDiagMove's requirement that one of the two side tiles be open. This is now on record as a rule the two were never meant to agree on, not a bug waiting to be fixed by accident: they differ on purpose.

The window exception reaches only the shooter's own grid

The exception is measured from the source, not the path: only the eight offsets inside the shooter's own 3x3 can ever cross a window at all. Of the owner's own tileflags.bin, 27 of 2048 tiles are windows, but only 9 of those block missiles at all, so the exception decides anything for those nine alone; the other 18 windows are already transparent to a shot at any range. 206 of 2048 tiles block a missile outright.

A hit stays, the list does not walk the path

The stop tile is written back only for a shot that fell short; a clean hit is left untouched, so it keeps the target the player chose. Every actor a shot crossed lands on the list in ascending object number order, not path order, because the list comes from walking the collision mask rather than walking the path again.

The wrong reading travels with the tests

All 18 new tests run against injected predicates, not against a file: the flags were already exported, so neither the data nor the export needed to change. The tile walk model is ported into the test suite itself, not just into this writeup, and asserted to disagree with the pixel walk on exactly the measured offsets, so a later tidy up cannot turn one into the other unnoticed.
