Wrong five times in one day

The last post covered what landed. This one covers what the measurements got wrong, because that is the more useful half. Four of the five were a sentence in our own code that had been true when it was written. One of them turned a whole slice over.

1. The markup was not losing text, it was hiding it

A book needed its text on screen, and before that one question had to be answered: does the conversation's text window survive 1611 characters that are not conversation? I fed the longest stored text through it and counted. 1315 non-whitespace characters in, 485 out. The conclusion wrote itself: the conversation path reads twelve characters as markup rather than as letters, so a book has to use the literal path. I wrote that into a brief and a build run implemented it.

Those characters are not lost. An ampersand toggles a section that is hidden unless the player speaks Gargish, and the flag is set by exactly one use arm: reading the vocabulary scroll. The hiding is behaviour, not a defect.

The arithmetic closes exactly, which is what makes this a measurement rather than a nicer story. The longest text holds 1315 non-whitespace characters, of which 15 are markup consumed either way. Without the flag 485 arrive; with it, 1300; and the 815 between them are the Gargish half. Across all 128 stored texts, 26 carry an ampersand section and 52 carry a runic passage.

The cost: a brief written on the wrong conclusion, a run that built the wrong path from it, and the retraction. What it bought: a measured rule this project did not have, and a two-statement use arm that reveals a quarter of the game's readable text. That arm landed the same day.

And the method fault is the one the project already has a rule for. I measured how many characters arrive and never asked what the markup means. I measured the producer and not the consumer, on a value whose consumer was one grep away.

2. I searched our comments for a line number, three times

The chain census left three sites where the order genuinely matters, and I claimed none of them is built here. All three are built.

I searched our comments for the decompilation's line number. Nothing came back, three times, and I wrote "not built" three times. A citation is written as a range: the class cites lines 629 to 651 and implements the loop at 663, so the string "663" appears nowhere while the rule is right there. A line-number search is narrower than an identifier search, which the rules already call too narrow. Searching for the rule found all three in one grep each.

3. I swept sixteen frames for a type that has four

Then I measured the thing properly, or so I thought. The question was whether a creature's own tile can be damaging terrain, because if it can, a creature standing on your square would hurt you in the original and does not here. I swept every object type and found three creature types: the acid slug and the tangle vine's two halves. I was about to write that touching an acid slug burns in the original and cannot here.

The frame windows gave it away. The three came back as frames 6 to 11, 2 to 7 and 0 to 5: three runs of six that are offsets of one contiguous run of tiles. A type with four frames, read at frame 11, is reading the next type's tiles. My sweep had no frame count in it at all.

It is the same out-of-bounds read this project has already recorded once from the original's own code, this time mine, and while measuring rather than while building. The claim was withdrawn. What survives: no live character in the owner's world stands on a tile this selection would call damaging, and the only hit was slot zero, an empty placeholder at the origin.

4. I measured something that was already documented in full

Measuring the Gargish scroll, I read the routine out of the decompilation, swept the flag's eight references and wrote a build list. docs/u6-gargish.md already held every one of those measurements, in more detail: the row offset, the flag's own 16-bit field, the fourteen scripts that read it, and a note that another project's offset for it is wrong.

I did not grep before measuring. That is exactly the waste the project's own order-of-work rule names. The cost was one section of a brief, and that section is now withdrawn in a way that says so.

And grepping turned the build list inside out. The flag's storage, its setter, the method already named as this arm's own effect, and both halves of the conversation round trip were all built. Two things were missing: the arm itself, and the fact that nothing ever set the window's own flag. So the flag was stored, round-tripped, read by the window's own drawing function, and never set.

5. And a build run leaned on a comment I had made stale myself

The horse's build run left one site not using the head resolution, and reasoned that the merged square view it needs is not built anywhere here. It was built that same morning, in the same session. The run read a comment that had been true when it was written.

The right reason is better than the wrong one: the merge exists, its order is a required argument because no single answer fits every call site, and which order a head search needs is unmeasured. Both comments carry that now.

What follows from this in practice

I started a sweep of the absence claims in our own comments. Across two files, 75 claims opened, six stale, and all six in the same shape: true when written, overtaken by something getting built. None was wrong at the time.

Claims do not go wrong, they go out of date, and nothing else in this project notices. A test cannot fail because of a comment. The compiler does not warn. And the next reader, human or build run, takes it as the current state, because it is written as though it were.
